# การวิเคราะห์ระบบ Telemetry และตัวชี้วัดที่อัปเดตเพิ่มเติม (Telemetry & Assessment Metrics Analysis)

เอกสารนี้สรุปโครงสร้างการเก็บข้อมูลพฤติกรรมผู้เล่น (Game Logs) และตัวชี้วัดการประเมินผลภายในเกม (In-Game Assessment Metrics) ที่ได้รับการอัปเดตเพิ่มเติมในระบบ Telemetry เพื่อให้สอดคล้องกับกรอบการวิจัยเรื่องการพัฒนาความสามารถในการป้องกันภัยคุกคามไซเบอร์ผ่านเกมจำลองสถานการณ์ (Scenario-Based Cybersecurity Game)

---

## 2. รายละเอียดตัวชี้วัดที่วัดผลเพิ่มขึ้น (5 หมวดหมู่หลัก)

### 2.1 การแยกวัด "เวลาคิดวิเคราะห์" vs "เวลาลงมือตัดสินใจ" (`BasePuzzleUI.gd`)
จากเดิมที่ระบบวัดเฉพาะเวลาที่ใช้ทั้งหมดตั้งแต่เปิดด่านจนจบ (`duration_seconds` / `time_taken_ms`) ระบบใหม่ได้เพิ่มตัวจับเวลา 2 ช่วงผ่านฟังก์ชัน `mark_decision_started()`:

* **`analysis_time_seconds` (เวลาที่ใช้ในการวิเคราะห์ข้อมูล)**:
  * **วิธีวัด**: นับตั้งแต่เปิดหน้าต่างโจทย์ (`_analysis_start_msec` ใน `start_puzzle()`) จนถึงวินาทีแรกที่ผู้เล่นเริ่มโต้ตอบหรือเลือกตัวเลือกคำตอบ (`_decision_start_msec`)
  * **ประโยชน์ในการวิเคราะห์**: ใช้วัดว่าผู้เล่นใช้เวลาอ่านหลักฐาน สังเกต Log หรือทำความเข้าใจสถานการณ์นานเพียงใดก่อนเริ่มลงมือตัดสินใจ
* **`decision_time_seconds` (เวลาที่ใช้ในการตัดสินใจและทดสอบวิธีแก้ปัญหา)**:
  * **วิธีวัด**: นับตั้งแต่วินาทีแรกที่ผู้เล่นเริ่มเลือกคำตอบ (`_decision_start_msec`) จนถึงตอนกดปุ่มยืนยันส่งคำตอบ (`submit_attempt()`)
  * **ประโยชน์ในการวิเคราะห์**: ใช้วัดความคล่องแคล่วและความมั่นใจในการเลือกแนวทางแก้ไขปัญหา

---

### 2.2 การวัดพฤติกรรมการลองผิดลองถูกและระดับคำใบ้ (`Trial-and-Error & Adaptive Scaffolding`)
ใน `BasePuzzleUI.gd` ได้เพิ่มการติดตามกระบวนการเรียนรู้ขณะแก้ปัญหาของผู้เล่นอย่างละเอียด:

* **`decision_history` (ประวัติการตัดสินใจรายครั้ง)**:
  * เก็บข้อมูลเป็น `Array` ของทุกครั้งที่ผู้เล่นกดส่งคำตอบในด่านนั้นๆ เพื่อใช้วิเคราะห์รูปแบบการลองผิดลองถูก (Trial-and-Error) โดยแต่ละรายการประกอบด้วย:
    ```json
    {
      "attempt": 1,
      "answer": "คำตอบหรือตัวเลือกที่ผู้เล่นทดสอบ",
      "is_correct": false,
      "duration_seconds": 18.4,
      "hint_tier": 1
    }
    ```
* **`hint_tier_reached` (ระดับคำใบ้สูงสุดที่ผู้เล่นเปิดดู: `0` ถึง `3`)**:
  * จากเดิมที่เก็บเพียง `hint_used` (`true`/`false`) ระบบใหม่รองรับคำใบ้ 3 ระดับ (`hint_tier_1`, `hint_tier_2`, `hint_tier_3`) และคำนวณผ่าน `get_adaptive_hint_tier()`:
    * **ระดับ `0`**: ไม่ได้เปิดใช้คำใบ้เลย
    * **ระดับ `1` (Nudge / ชี้จุดสังเกต)**: บอกใบ้ตำแหน่งหรือจุดผิดปกติเบื้องต้น
    * **ระดับ `2` (Concept / อธิบายหลักการ)**: อธิบายหลักการทางเทคนิคที่เกี่ยวข้อง (ผู้เล่นกลุ่ม `Beginner` จะได้รับสิทธิ์เริ่มที่ระดับนี้ทันทีหากเปิดโหมด Adaptive)
    * **ระดับ `3` (Actionable Guidance / แนวทางแก้ไขเชิงลึก)**: แนะนำขั้นตอนการแก้ไขเมื่อผู้เล่นลองผิดเกินจำนวนครั้งที่กำหนด

### 2.3 การวัดผลความรู้พื้นฐานก่อนเรียน (`10-Point Pre-test` ใน `typing_game.gd`)
ในด่าน `T04` (`P00` - MS Word `Report_Final.docx`) ได้เปลี่ยนจากการวัดความเร็วพิมพ์ดีดอย่างเดียว มาเป็นการวัดความรู้พื้นฐานด้านความมั่นคงปลอดภัยไซเบอร์จำนวน **10 คะแนน** (โดยยังคงฟิลด์ `wpm` และ `accuracy` ไว้เพื่อรักษาความเข้ากันได้กับสัญญา API ใน `tests/test_analytics_contract.py`):

| ชื่อตัวชี้วัด (Metric Key) | ชนิดข้อมูล | คะแนนเต็ม / ความหมาย |
| :--- | :--- | :--- |
| `assessment_type` | `String` | มีค่าเป็น `"pretest"` เพื่อระบุว่าเป็นข้อมูลวัดผลก่อนเริ่มเหตุการณ์ |
| `pretest_score` | `int` | คะแนนรวมที่ผู้เล่นทำได้ในรอบนั้น (`0–10` คะแนน) |
| `max_score` | `int` | คะแนนเต็มของแบบทดสอบ (`10` คะแนน) |
| `dropdown_score` | `int` | **คะแนนส่วนที่ 1 (`0–6` คะแนน)**: การเลือก Dropdown เติมคำศัพท์เทคนิคในย่อหน้ารายงาน 6 ช่อง (`Typosquatting`, `Ransomware/Wiper`, `Network Isolation`, `Forensic Image`, `File Hash / MD5`, `3-2-1 Backup Rule`) |
| `checkbox_score` | `int` | **คะแนนส่วนที่ 2 (`0–2` คะแนน)**: การวิเคราะห์แผนภาพ **Figure 1** แบบติ๊กเลือกคำตอบ (โครงสร้างไฟล์ `.docx` ที่ซ่อนเพย์โหลด `Base64/Hex` และการเตรียมเครื่องวิเคราะห์แยกส่วน) |
| `dragdrop_score` | `int` | **คะแนนส่วนที่ 3 (`0–2` คะแนน)**: การจัดเรียงลำดับแผนผัง **Figure 2 Flowchart** แบบ Drag-and-Drop 4 ขั้นตอน (`ตรวจ Log` -> `เข้า Safe Mode` -> `ปิด Scheduled Task` -> `กู้คืนจาก Backup`) |
| `analysis_duration_seconds` | `float` | เวลาที่ผู้เล่นใช้อ่านเนื้อหารายงานก่อนเริ่มคลิกทำข้อสอบข้อแรก |
| `decision_duration_seconds` | `float` | เวลาตั้งแต่เริ่มทำข้อสอบข้อแรกจนกดปุ่มส่งรายงาน |

### 2.4 การจัดกลุ่ม 4 Scenarios และการวัดสมรรถนะ 3 ด้านตามบทคัดย่อ (`TelemetryManager.gd` & `ksa_evaluation.gd`)

#### 1) การผูกภารกิจเข้ากับ 4 สถานการณ์จำลอง (`SCENARIO_MAPPING`)
ทุกครั้งที่มีการเรียก `TelemetryManager.log_event()` ระบบจะระบุ `metrics["scenario_id"]` ให้อัตโนมัติผ่าน `get_scenario_for_task()`:
* **`Scenario_1` (การเตรียมสภาพแวดล้อมและระบุสาเหตุเบื้องต้น)**: `T01`, `T02`, `T03`, `T04` (`Task_04`), `T05`
* **`Scenario_2` (การสืบสวนทางนิติวิทยาศาสตร์ดิจิทัล)**: `T06` (`Task_06`), `T07` (`Task_07`), `T08` (`Task_08`), `T09`, `T10` (`Task_11`), `T11` (`Task_13`)
* **`Scenario_3` (การเลือกและทดสอบวิธีแก้ปัญหาแบบลองผิดลองถูก)**: `T12` (`Task_14` - การหยุด Persistence), `T13` (`Task_15` - การกู้คืนตามกฎ 3-2-1)
* **`Scenario_4` (การสรุปองค์ความรู้และการประเมินผลในเกม)**: `T14` (`Task_16` - รายงานสรุปเหตุการณ์), `T15` (สรุปผลการประเมิน)

#### 2) คะแนนสมรรถนะท้ายเกม 6 มิติ (`get_assessment_summary()`)
ในด่านสุดท้าย `T15` (`ksa_evaluation.gd`) ระบบคำนวณและส่งคะแนนออกเป็น 2 กรอบควบคู่กัน (แต่ละด้านมีค่า `0–100` คะแนน):
1. **กรอบ K-S-A เดิม**:
   * `knowledge_score`: ความรู้ความเข้าใจด้านภัยคุกคามไซเบอร์
   * `skills_score`: ทักษะการปฏิบัติงานสืบสวนและแก้ไขปัญหา
   * `attitude_score`: ทัศนคติและความตระหนักรู้ในการระมัดระวังภัย
2. **กรอบสมรรถนะ 3 ด้านตามบทคัดย่องานวิจัย (เพิ่มใหม่)**:
   * **`cause_analysis_score` (ความสามารถในการวิเคราะห์สาเหตุ)**: คำนวณจากอัตราความสำเร็จของภารกิจวิเคราะห์และสืบสวน (`T04` ถึง `T11`)
   * **`problem_solving_score` (ความสามารถในการแก้ปัญหาและกู้คืนระบบ)**: คำนวณจากอัตราความสำเร็จของภารกิจหยุดการทำงานของมัลแวร์และกู้คืนข้อมูล (`T12`, `T13`)
   * **`prevention_score` (ความสามารถในการป้องกันแรนซัมแวร์)**: คำนวณจากอัตราความสำเร็จของการสรุปแนวทางป้องกันในรายงานและการประเมินผล (`T14`, `T15`)

### 2.5 ระบบบันทึก Game Logs ลงไฟล์ในเครื่องอัตโนมัติ (`_save_local_log()`)
เพื่อให้ผู้วิจัยสามารถนำข้อมูล Game Logs ไปวิเคราะห์ทางสถิติได้ทันทีแม้ในสภาพแวดล้อมที่ไม่ได้เชื่อมต่อเซิร์ฟเวอร์ Backend ฟังก์ชัน `TelemetryManager._save_local_log()` จะบันทึกไฟล์ลงในโฟลเดอร์ `user://` ของ Godot โดยอัตโนมัติ:

1. **`user://scenario_game_logs.json`**:
   * บันทึกข้อมูลดิบทุก Event ในรูปแบบ JSON Lines (บรรทัดละ 1 JSON Object) ครอบคลุมทั้ง `metrics`, `decision_history`, และคะแนนย่อยทั้งหมด
2. **`user://scenario_game_summary.csv`**:
   * บันทึกตารางสรุปผลรายภารกิจในรูปแบบ CSV ที่เปิดด้วย Excel / R / Python (`pandas`) ได้ทันที โดยมีคอลัมน์มาตรฐานดังนี้:
     ```csv
     timestamp,session_id,player_id,scenario_id,task_id,attempt_count,hint_used,analysis_time_seconds,decision_time_seconds,total_duration_seconds,is_correct
     ```

## 3. ตารางเปรียบเทียบตัวชี้วัดก่อนและหลังอัปเดต (Before vs. After)

| หมวดหมู่การวัดผล | ก่อนอัปเดต (Before) | หลังอัปเดต (After) |
| :--- | :--- | :--- |
| **การจับเวลารายด่าน** | วัดเฉพาะเวลารวม (`duration_seconds` / `time_taken_ms`) | แยกวัด **เวลาวิเคราะห์ (`analysis_time_seconds`)** และ **เวลาตัดสินใจ (`decision_time_seconds`)** |
| **การใช้คำใบ้ (Scaffolding)** | วัดเฉพาะสถานะเปิด/ไม่เปิด (`hint_used: bool`) | วัด **ระดับคำใบ้สูงสุด (`hint_tier_reached: 0–3`)** ที่ปรับตามกลุ่มผู้เล่น (`Beginner`/`Expert`) |
| **พฤติกรรมการลองผิดลองถูก** | นับเฉพาะจำนวนครั้งที่ส่งคำตอบ (`attempt_count`) | เก็บ **ประวัติลำดับการเลือกคำตอบทุกครั้ง (`decision_history`)** พร้อมผลลัพธ์และเวลาในแต่ละรอบ |
| **การวัดผลก่อนเรียน (`T04`)** | วัดเฉพาะความเร็วพิมพ์ดีด (`wpm`, `accuracy`) | วัด **`pretest_score` (เต็ม 10)** แยกย่อยเป็น `dropdown_score` (6), `checkbox_score` (2), `dragdrop_score` (2) |
| **สมรรถนะท้ายเกม (`T15`)** | วัดเฉพาะ 3 ด้าน K-S-A (`knowledge`, `skills`, `attitude`) | เพิ่มสมรรถนะ 3 ด้านตามบทคัดย่อ: **`cause_analysis_score`**, **`problem_solving_score`**, **`prevention_score`** |
| **การจัดหมวดหมู่ & Export** | ส่งผ่าน HTTP ไปยัง Backend API เท่านั้น | ผูก **`scenario_id` (`Scenario_1`–`4`)** อัตโนมัติ + บันทึกไฟล์ **`scenario_game_logs.json`** และ **`scenario_game_summary.csv`** ลงเครื่อง |
